# 关键逻辑说明

## 发布与版本

`validateSurveyLogic` 先逐题检查输入结构、重复题号及规则条件，再检查目标题号、自跳转与图中的环。图同时包含显式跳转边和顺序下一题边。只有校验通过才能发布。后端将草稿复制进新的 `survey_versions.questions`，版本号递增，随后更新 `surveys.publishedVersionId`；旧快照不覆盖。

已发布问卷调用 `/draft` 时从当前快照复制出编辑草稿，公开填写仍使用当前发布快照。再发布后，新打开的页面获取新版本；旧页面继续按它打开时的 `versionId` 填写和提交。关闭的问卷不能再编辑或新提交。发布涉及两次数据库写入，发生普通错误会尝试删除新快照；进程在两次写入之间崩溃仍可能留下未引用版本。

## 答案与跳转

`validateAnswer` 校验题号、题型、必答状态与题型参数：单选只能选已有 ID；多选不能重复，遵守最少、最多和精确数量；文本检查长度；数字与评分检查范围及整数要求。

`resolveNextQuestion` 顺序判断 `jumpRules`，第一条命中决定下一题。多选支持包含单项、包含任一、同时包含全部、恰好选择指定集合、未选择任何指定项。数字与评分支持大小、相等和含边界区间。可选多选未作答按空选择判断排除条件。未命中时按题目数组顺序前进，末题之后返回 `null`。

`/next` 只引导页面显示。最终 `/submit` 的 `replayPath` 从指定版本第一题重新出发，逐题校验答案、计算下一题并记录 `path`；检测重复答案、无效目标、循环和路径外答案。合法跳过的必答题不要求作答。这样不能靠客户端伪造路径绕过校验。

## 幂等、匿名与关闭

一次提交由 `clientSubmissionId` 标识。服务端基于用户与问卷计算 HMAC `respondentKey`，MongoDB 唯一索引保证同一问卷、同一用户、同一提交 ID 只保存一份；重复请求返回已有答卷。当 `allowMultiple=false` 时，唯一部分索引上的 `dedupeKey` 还会拦截换提交 ID 的再次填写。匿名答卷的 `respondentId` 为 `null`，但仍可通过内部稳定标识执行这些约束；统计接口不投影身份字段。

`closeExpiredSurveys` 将已到期且仍为 `published` 的问卷更新为 `closed`。服务启动时、每 30 秒及相关请求读取时均会核对；创建者也能主动关闭。关闭后新公开读取和新提交被拒绝，原有版本与统计保留。同键已保存答卷的重试会先返回原提交回执。

## MongoDB 聚合统计

整卷和单题统计共用 `getStatistics`。管道先 `$match` 问卷 ID 和版本 ID，`$project` 只保留答案与提交时间，然后 `$facet` 同时计算总答卷数和各题结果。每题先 `$unwind` 答案：单选按选项 `$group`，多选再次 `$unwind` 选项数组后计数；文本排除空白并按提交顺序收集；数字与评分计算回答数、平均值、最小值、最大值及原值。格式化阶段按版本题目补齐未选项的零计数。整卷总答卷数与某道题实际回答数可以不同。当前文本和数字原值没有分页。
