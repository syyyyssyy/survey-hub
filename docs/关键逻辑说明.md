# 关键逻辑说明（第二阶段）

## 核心设计

题库与问卷采用不同身份：逻辑题 ID 用于跨问卷识别，题目版本 ID 指向被选用的内容，问卷 qid 用于本卷题序、答案和跳转，问卷发布快照 ID 则标识一次发布。src/library.js 在原 Express 应用中挂载路由；题目结构继续由 src/schemas.js 校验，发布和填写仍由原规则引擎完成。

## 题库复用、分享与版本

1. **存入题库**：先验证问卷所有权和草稿编辑权限，提取题干、题型、选项、必答及校验配置，不保存跳转目标。创建 library_questions 和 v1，再给母本草稿题写来源 ID。对同一问卷中 qid、内容均吻合且未带来源 ID 的旧发布快照，记录 originRefs；不改旧快照和答卷。直接创建题库题则没有母本来源。
2. **从题库选题**：核对题目属于当前用户且未归档，复制指定 question_versions.content 到草稿，生成本卷 qid 并令 jumpRules 为空。批量选题先检查整组版本，随后一次保存问卷草稿。问卷本地只改题序或跳转规则时可保留来源；改题意、选项或校验配置后清除来源，避免统计误归属。
3. **链接分享**：所有者生成随机令牌，库中只存 SHA-256 哈希。接收者凭令牌导入时，后端创建归接收者所有的新逻辑题和 v1 内容副本；同一链接可由多人使用。原题后来覆盖、归档或撤销链接，都不改变已经导入的副本。
4. **新建版本与默认版本**：新建时取历史最大版本号加一，插入新的 question_versions 文档，并把 currentVersionId 指向它；已有问卷保持原内容。点击“设为默认版本”只改变 currentVersionId，不复制旧版产生新版本。
5. **覆盖指定版本**：先检查本人草稿与当前发布快照中仍引用该版本的题，并验证替换后题目结构与发布跳转图。随后更新该题目版本，增加 contentRevision，并把覆盖前内容放入 contentHistory；本人相关草稿同步修改，受影响的当前已发布问卷新增 survey_versions 快照并切换 publishedVersionId。旧发布快照、旧答卷和其他用户的导入副本保持原样。跨多个文档的更新目前未使用事务，异常中断时存在部分更新风险。
6. **归档与使用查询**：批量归档写 archivedAt，并使分享令牌失效；仅从可用题库列表隐藏。使用查询按当前用户的草稿来源 ID、发布快照来源 ID 和明确记录的母本 originRefs 返回位置，不据同名题干猜测关联。

## 发布、校验与跳转

发布时 src/survey-logic.js 检查非空题目、题号唯一、规则条件与题型相符、目标存在且不指向自身。它把每条跳转边和未命中时可能走的顺序边组成图，用 DFS 检测环；有环或无效目标就拒绝发布。通过后在 survey_versions 新增快照，再切换 surveys.publishedVersionId。关闭与截止日期逻辑把问卷状态改为 closed，历史数据不删除。

- validateAnswer：核对 qid、题型、必答与空值；单选检查选项成员，多选检查选项成员、重复以及最少/最多/精确选择数，文本检查长度，数字与评分检查类型、范围和整数条件。限制来自题目 validation 数据，更改阈值不需重写校验函数。
- resolveNextQuestion：按 jumpRules 顺序解释条件，第一条命中即返回 targetQid。单选匹配选项；多选支持包含单项、包含任一、包含全部、恰好指定组合、未选择任何指定选项；数字和评分支持大小比较及含边界区间。未命中时走数组中的下一题，末题后返回 null。
- replayPath：提交时从版本第一题重新遍历，调用前两函数逐题校验和决定下一题，记录实际路径；拒绝重复答案、未知目标、循环以及路径外答案。合法跳过的必答题不需填写。前端的 /next 只负责导航，不能代替最终提交校验。

## 提交、匿名与统计

答卷提交必须带填写时取得的问卷 versionId。服务端先查同一 respondentKey 与 clientSubmissionId 的已保存答卷；命中则返回原回执。新请求通过路径重放后才写入 responses。唯一索引解决并发重试；问卷不允许重复填写时，dedupeKey 的唯一部分索引阻止同一人换提交 ID 再提交。匿名提交的 respondentId 为 null，内部 respondentKey 仍服务于幂等，但创建者统计接口只聚合答案，不返回这些身份字段。

单卷统计由 src/statistics.js 按 surveyId 和 versionId 筛选，使用 $facet、$unwind、$group 计算总答卷数、选项次数、文本内容以及数字/评分的平均值和范围。单选题的本题回答数与整卷答卷数分开。题库跨问卷统计先限制所有者自己的问卷，用作答 versionId 关联发布快照，再用题库来源 ID、qid 或明确的 originRefs 找答案；按逻辑题的具体版本和 contentRevision 分组，不混合不同题意，也不汇总导入者的独立副本。另从快照聚合 surveyVersionCount，使零回答时也能看到纳入范围。

## 验证与边界

对应的 API 集成和规则单元测试位于 tests/；真实运行命令及结果见 tests/测试用例.md。MongoDB 初始化脚本可重复运行，旧问卷题缺少题库来源字段时仍能按原问卷读取和统计。没有来源证据的历史题不会自动凭题干相同并入题库统计。当前未做高负载或浏览器端自动化点击测试；大规模文本或数字原始值统计未分页。
