# 系统说明

## 目标与范围

本系统使用 Node.js、Express 和 MongoDB 实现问卷创建、发布、填写与统计。填写者需登录；问卷创建者只能管理自己的问卷。前端为 `public/` 中的单页应用，后端通过 `/api` 提供 JSON 接口。

当前支持单选、多选、文本填空、数字填空和整数评分题。多选可限制最少、最多或精确选择数；文本可限制长度，数字可限制范围与是否仅整数。题目可配置条件跳转。问卷允许设置截止时间、匿名填写和是否允许同一用户重复提交。创建者可以主动关闭问卷。

## 模块与目录

| 位置 | 职责 |
|---|---|
| `public/` | 题目编辑、填写导航、统计展示 |
| `src/app.js` | API、登录鉴权、问卷管理、版本发布、答卷提交 |
| `src/schemas.js` | Zod 请求与题目结构校验 |
| `src/rule-engine.js` | 答案校验、下一题判断、提交路径重放 |
| `src/survey-logic.js` | 发布前检查题目及跳转图 |
| `src/survey-status.js` | 到期关闭问卷 |
| `src/statistics.js` | MongoDB 聚合统计 |
| `database/init-mongodb.js` | 四个集合的 `$jsonSchema` 与索引 |
| `tests/` | 六个自动化测试文件与测试用例说明 |

## 业务流程

1. 创建者注册并创建草稿问卷，设置题目、选项、校验参数和跳转规则。草稿可整组保存并重排题号。
2. 发布时，服务端检查规则目标与环，在 `survey_versions` 插入冻结的题目快照，再更新问卷的当前版本指针。
3. 已发布问卷需要编辑时，创建者打开编辑草稿。新版本发布前，公开填写仍使用旧版；新版本发布后，已打开的旧版页面可携带原 `versionId` 完成提交。
4. 填写页面逐题调用下一题接口。最终提交时服务端依据所属版本重新校验答案和路径，拒绝路径外答案，然后保存绑定该版本的答卷。
5. 创建者查看整卷或单题统计，可按 `versionId` 查看历史版本。问卷关闭后不接受新的填写，历史答卷和统计保留。

## 运行与边界

安装、数据库初始化、环境变量和测试命令见根目录 [README](../README.md)。所有公开填写接口仍要求登录；匿名只对创建者隐藏身份。系统没有“跳到结束问卷”的规则目标，末题答完后自然结束。发布快照与更新当前版本指针是两次数据库写入，当前未使用事务；大量文本或数字原始答案的统计结果尚未分页。浏览器自动化点击测试尚未执行。
