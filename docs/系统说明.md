# 系统说明（第二阶段）

## 系统目标与边界

SurveyHub 是基于 Node.js、Express 和 MongoDB 的问卷系统。用户登录后可以创建和填写问卷；第二阶段在原有问卷流程上增加常用题目复用、题库管理、链接导入独立副本、题目版本、使用情况查询及跨问卷统计。系统仍以问卷为填写单位：题库负责复用内容，跳转目标只属于某一份问卷。

## 架构与模块

浏览器页面（public/）通过 JSON API 与 Express 服务通信；服务用 MongoDB 保存用户、问卷、发布快照、答卷和题库数据。填写时浏览器负责显示题目，服务端负责最终校验、决定路径并保存答卷。

| 模块 | 位置 | 主要职责 |
|---|---|---|
| 页面 | public/index.html、public/app.js、public/styles.css | 问卷与题库管理、逐题填写、统计展示；题型配置按需显示 |
| API 与鉴权 | src/app.js | 登录、问卷草稿、发布、关闭、填写及单卷统计；校验所有权 |
| 题库服务 | src/library.js | 默认/命名题库、存题、批量选题、分享链接、版本、使用情况 |
| 结构与规则校验 | src/schemas.js、src/survey-logic.js | Zod 输入校验、发布前检查目标题号与跳转环 |
| 作答引擎 | src/rule-engine.js | 按题型验证答案、解释跳转条件、重放实际答题路径 |
| 状态与统计 | src/survey-status.js、src/statistics.js | 截止日期关闭；MongoDB 聚合单卷和跨问卷结果 |
| 数据库初始化 | database/init-mongodb.js | 七个集合的 $jsonSchema 校验器和索引 |

这样划分是因为题库版本、问卷编辑、作答校验和统计的变化速度不同。新增题库只在原问卷题上增加可选来源标识，填写与发布仍复用已有模块。

## 用户与主要流程

- **创建者**：管理自己的问卷和题库；可查看自己问卷的历史版本、答卷统计和题目使用情况。不能读取他人的私有题库或问卷。
- **填写者**：登录后通过公开链接填写已发布且未关闭的问卷；可按问卷设置匿名或重复提交。匿名仅隐藏创建者可见身份，服务端保留防重复所需的内部标识。
- **题库复用**：用户可直接存入默认题库（无需创建命名题库），或存入自己的命名题库。选入问卷时复制指定版本的题目内容，清空旧跳转规则并生成本卷题号；可按题库全选和批量选入。
- **链接导入**：所有者生成可重复使用的分享链接。其他用户导入时会得到自己名下的新逻辑题和初始版本；此后双方编辑、归档及统计互不影响。
- **题目版本**：编辑时可新建版本，也可明确选择覆盖指定版本。新建版本不改变既有问卷；覆盖会更新本人仍使用该版本的草稿，对受影响的当前已发布问卷新增发布快照并切换当前版本。旧快照和历史答卷不改。选择旧版为默认只改默认指针。
- **问卷发布与填写**：草稿可增删和重排题目。发布前检查题目与跳转规则；通过后新增发布快照。填写页取得当时的 versionId，提交时服务端按该快照重放路径。问卷可主动关闭，到期也会自动变为已关闭。
- **统计**：单卷支持整卷、单题和按问卷版本查看；题库题支持按题目版本及内容修订查看本人多份问卷的结果，包括存题时的母本和纳入的问卷版本数。

## 运行、文档与限制

运行需要 Node.js、MongoDB 和项目依赖；依次执行 npm.cmd ci、数据库初始化脚本，再配置至少 32 字符的 SESSION_SECRET 并运行 npm.cmd start。详细命令见项目根目录 README。测试用例及实际结果见 tests/测试用例.md。

本项目没有浏览器端自动化点击测试。题库版本覆盖和问卷快照切换涉及多文档写入，目前没有 MongoDB 事务；进程在中途异常退出时可能需要检查一致性。跨问卷统计只汇总题目所有者自己的问卷，不合并其他用户导入后的独立副本。
